# Codebook dependency manifest

When the codebook changes (rename a sub-action, add/remove an instance, restructure a category, bump a count), several artifacts in this repo must be kept in sync. This file is the canonical "what to update next" checklist.

The codebook has 6 tiers: **(1) canonical sources** → **(2) derived data files** → **(3) skill: trace-qualitative-analyst** → **(4) project READMEs** → **(5) skill: discovery-qualitative-analyst)** → **(6) frozen records**. A change to any source-of-truth file should propagate down.

---

## Tier 1 — Source of truth

The visual master records the reviewed hierarchy. Keep the structured sources below aligned when accepting a codebook change; a repository refactor does not revise these research artifacts.

| File | What it holds | Edit when |
|---|---|---|
| `data/taxonomy/taxonomy_development/Action Space Codebook (V4.2).pdf` | Visual master — the authoritative layout of all Actions, Subactions, and Instances (three-level hierarchy aligned with arXiv:2605.13625v1) | Whenever the taxonomy changes (re-export from Google Docs / source) |

## Tier 2 — Derived structured data (update after editing Tier 1)

These files must be manually updated to reflect every change made in the PDF.

| File | What it holds | Update when |
|---|---|---|
| `data/taxonomy/act-onomy_codebook.csv` | Action / Subaction / Instance + `examples_raw` + `papers_cited` + `human reviewers`, one row per leaf (120 leaves) | Any leaf-level change |
| `data/taxonomy/act-onomy_taxonomy.csv` | Same hierarchy + `definition` column | Any leaf-level change — keep in lockstep with codebook.csv |
| `data/taxonomy/act-onomy_taxonomy.json` | Tree form + `summary` (`tier_1`=actions, `tier_2`=subactions, `tier_3`=instances) | When restructuring; update `summary` if structure changes |
| `data/taxonomy/taxonomy_development/codebook_v4.2.json` | Rich tree form (action → sub → leaves) + `summary` (`n_actions`, `n_sub_categories`, `n_leaves`) + `version_note` | Any structural change; bump `version_note` |
| `hf_release/taxonomy/act-onomy_codebook.csv` | Mirror of `data/taxonomy/act-onomy_codebook.csv` | Copy after editing above |
| `hf_release/taxonomy/act-onomy_taxonomy.csv` | Mirror of `data/taxonomy/act-onomy_taxonomy.csv` | Copy after editing above |
| `hf_release/taxonomy/act-onomy_taxonomy.json` | Mirror of `data/taxonomy/act-onomy_taxonomy.json` | Copy after editing above |
| `data/taxonomy/taxonomy.md` | Curated taxonomy and paper-grounded frequencies | Manual review against the paper; not regenerated by scripts |
| `hf_release/taxonomy/taxonomy.md` | Optional local release copy | Explicit copy after review |

**Invariant.** All four structured files (two CSVs + two JSONs) must agree on the set of (Action, Subaction, Instance) tuples. Discrepancies are bugs.

## Standard runbook — "I just changed the codebook"

1. **Edit Tier 1** — update `data/taxonomy/taxonomy_development/Action Space Codebook (V4.2).pdf` (re-export from Google Docs).
2. **Update Tier 2 structured files** — modify `act-onomy_codebook.csv` and `act-onomy_taxonomy.csv` (in lockstep). For structural changes, also update `codebook_v4.2.json` and bump its `version_note`; sync `summary` counts in both JSON files.
3. **Generate the full codebook** — run `python3 scripts/actonomy.py codebook` to write `outputs/codebook_v4.2.md`. Review the curated taxonomy and paper frequencies manually. Update local release staging explicitly when preparing a release.
4. **Update Tier 3** (skill) — patch `references/codebook.md` (subgroup list + count); patch `SKILL.md` / `README.md` if counts or sample names changed; migrate `example_pylint_5859.json` if any used subgroup was renamed; run `render_artifact.py` to verify 0 warnings.
5. **Update Tier 4** (READMEs) — bump `N Subactions` in 2 files (3 lines).
6. **Decide on Tier 5** — only update illustrative example names if you want them to track current naming.
7. **Skip Tier 6** — never modify frozen records.

**Final verification:**

```bash
make check
python3 scripts/actonomy.py demo
```

The repository checker covers structural agreement, counts, palette groups, and worked-example action/subaction pairs. It does not semantically validate every dependency listed here. Release staging, external manuscripts, and personal skills remain explicit review tasks.
