Annotation contract · C1–C6

From the human-IRR study (AC-Q2 .../irr/, blind pass by a codebook-fluent human against all three stacks). Two of these change what gets quoted, so they override the general heuristics and any precedent below that predates them.

C1 · Quote the action surface, not only the thought

Set quote_target: "both" and give every quote a "target": "thought" or "target": "action" field.

Batch-3 quoted thoughts only — all 922 spans across the three stacks sit in thought, none in action. But every Executing leaf is defined by a command being run (Apply patch via edit — "running an edit command"; Run verification command — "running python, pytest"). So Executing could never be evidenced by the field it was defined on, and the stacks resolved that by projecting the turn's command back onto the thought that announced it. The human annotator, reading the glosses literally, used Executing zero times in 41 quotes. That is not a miss; it is the only self-consistent reading of a thought-only contract.

C2 · A thought that announces an action is Planning; the action span carries Executing

就句论句 — the sentence is judged on what it says. In thought, expect Planning, at most Evaluating. Executing belongs to the action span.

C1 is what makes C2 payable: the execution still gets labelled, on the span that actually executes. Under a thought-only contract C2 alone would simply delete Executing from the data.

Worked pair (astropy T15, sympy T3, scikit-learn T3 and five more):

span field label
"run the script to see if we can reproduce the issue" thought Planning > Formulate a workflow or plan > Plan function or tool use
python reproduce_issue.py action Executing > Executing plan > Run verification command

In all eight blind-pass collisions of this shape the turn's action literally performed what the thought announced, and the stacks labelled the thought Executing while the human labelled it Planning. Both were right about the turn; the contract had not said which span owns the execution. Now it has.

C3 · Precedents superseded by C1 and C2

25 adjudicated patterns covering 65 spans put a thought span into Executing. They were adjudicated correctly under the thought-only contract and are kept below as history, but for thought spans they no longer apply:

  • R1 (P002, P003, P144, P153, P158 — 36 spans, "run it / test our changes by running …") → the thought span is now Planning; Run verification command moves to the action span.
  • Apply patch via edit on thought spans (P009, P015, P019, P027, P038, P049, P085, P093, P094, P110 — 17 spans) → thought span is now Planning; Apply patch via edit moves to the edit … action span.
  • Initiate planned action / Normal executing / Adopt debugging instructions on thought spans (P011, P020, P033, P034, P037, P047, P057, P060, P062, P063 — 12 spans) → same move.

An Executing label on an action-targeted span is unaffected — there were none before, because there were no action spans.

This supersession has not been re-adjudicated span by span. It is a stated rule, not 65 fresh human calls. Any batch built under this contract is a new annotation contract, not a re-run of batch-3, and is not span-comparable with batch-3. Say so wherever its numbers are reported.

C4 · When two leaves genuinely will not separate

Pick the leaf whose gloss fits the span most tightly, record the collision, and move on. Do not break the tie by model majority, and do not leave the label blank — a blank loses the span, while a recorded collision is evidence for the next codebook version.

C6 · Retrieval vs Grounding on a phrase that will not split

From the human-IRR pass on pydata__xarray-3305 (Q9 · T18). When a phrase cannot be split into an operation part and an object part, decide on what the phrase actually states:

the phrase states label example
only the operation Grounding "Let's open the file"
the object it acts on, or the information it is after Retrieval "inspect the implementation of resolve_expression"

Scope: thought spans. Command surfaces are unresolved. The span that prompted this rule is an action span, search_file "def quantile" xarray/core/dataset.py, where the human took Grounding > Augment with external computation > Execute code and all three stacks took Retrieval > Retrieve from local corpus. Read literally the rule above sends that span to Retrieval, since it names both the pattern searched for and the file, so the rule does not reproduce the label that prompted it. Do not extend C6 to action spans until that call is made.

The same annotator proposed a leaf that would dissolve the conflict rather than arbitrate it: Grounding > Augment with external computation > Search relevant files. search_file would land there, and the boundary rule would not have to cover command surfaces at all. Recorded in irr/codebook_notes.md, not yet in the canonical codebook.

Standing evidence: Grounding ↔ Retrieval is the largest cross-model confusion pair in batch-4, 112 of 545 action-level disagreements (20.6%), up from 28 (8.0%) in batch-3. See analysis/IRR_batch-4.md.
